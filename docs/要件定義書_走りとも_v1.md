## 1. 概要

### 1.1 目的

車・バイク好き同士を、**本人の素顔ではなく趣味・中身ベース**でマッチングし、以下を実現する。

1. 一般ユーザー同士：今から・近くで、走りとも（走行会・ツーリング・オフ会仲間）を探して一緒に走る
2. 一般ユーザー：近くの立ち寄り施設（ガソリンスタンド・道の駅・展望台）を探してGoogleマップで開く
3. 一般ユーザー：使わなくなったパーツ・用品・工具を近隣で無償でゆずりあう・交換する
4. ビジネスユーザー：AI接客・地図連携で、近隣の走り好きに店舗（GS・整備工場・カー用品店・道の駅等）を知ってもらい来店へつなげる
5. コミュニティ：走行会サークル、オフ会、写真撮影会などのイベント企画

### 1.2 コンセプト上の設計原則

| 原則 | 内容 |
|---|---|
| 本人の素顔画像禁止 | プロフィール画像は「車・バイク・整備風景に関連する画像のみ」許可。本人の素顔がメインの画像・ナンバーが判読できる画像はアップロード不可（モデレーションで拒否・削除） |
| 公道の安全 | 公道での走行は交通ルール・マナー遵守を常に案内。公道レース・危険運転の募集は禁止文言で排除 |
| 恋愛目的禁止 | 利用規約で「恋愛・異性交際目的の利用」を明示的に禁止。違反は BAN 対象 |
| 金銭取引禁止 | ゆずりあい・交換は無償の譲り合い・物々交換のみ。パーツの売買・オークション的な利用は禁止 |
| 時限性 | 募集は期限付き（1〜3時間）。期限が来たら自動消滅。「今から」感が出会い系化を防ぐ |
| 距離の粗表示 | 正確な位置は非公開。「〜1km / 1〜3km」のような大ざっぱな距離のみ表示 |

### 1.3 前提と未確定事項（法務レビュー必須）

| 項目 | v1 の対応 | 備考 |
|---|---|---|
| 出会い系サイト規制法 | サービスの実質を「走り仲間探し」とし、規約・モデレーションで異性交際目的利用を排除 | 弁護士による非該当性確認を必須とする。素顔画像禁止・一言メッセージ制は非該当性の根拠になる設計 |
| 未成年利用 | **v1 は18歳以上のみとする**（シリーズ各弾と同じ） | 運転免許との関係で実質18歳以上。未成年対応はv2以降で法務確認の上検討 |
| 道路交通法・違法走行 | 公道での走行は法定速度・マナー遵守を常時案内。サーキット・場内での走行会を推奨。危険運転の兆候のある募集は通報・削除対象 | 走行会の主催責任・免責規約の整備 |
| 迷惑防止条例（客引き） | ビジネスユーザーの営業・AI接客はアプリ内完結とし、押しつけのない設計（一斉配信はしない）。オプトアウト手段を常時提供 | 個別自治体への確認は開発中に実施 |
| 個人情報保護法 | 位置情報・嗜好データの第三者提供は「匿名加工統計」に限定 | 店舗ダッシュボードには集計値のみ表示 |
| 受け渡しの安全 | ゆずりあい・交換の受け渡しは公共の駐車場・道の駅を前提とし、個人の自宅住所等を記入させない案内。金銭授与・送金を伴う取引は禁止 | トラブルを想定した免責規約の整備 |

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 一般ユーザー | 無料で利用する走り好き（個人。車・バイクどちらも可）。走りともを探す側 |
| ビジネスユーザー | 有料プランで登録する店舗・事業者・個人営業主（ガソリンスタンド、カーショップ・整備工場、カー用品店、ドライブイン・道の駅、サーキット・走行会場、バイクショップ、レンタカー・レンタルバイク、洗車場など） |
| 募集（Recruitment） | ユーザーが近隣に向けて時限で発信する「参加者募集」（走行会・サーキット / ツーリング・ドライブ / オフ会・ミーティング）。投稿から1/2/3時間後に自動消滅 |
| 応募（Application） | 募集への参加申請。主催者が承認するとグループチャットが生成される |
| コミュニティ | 常設のグループ（走行会サークル、旧車オフ会、GS常連会等）。誰でも作成可、参加自由（承認制も選択可） |
| イベント | コミュニティまたは個人が企画する日程付きの集まり（走行会、朝ツー、整備オフ会など） |
| 施設検索 | 現在地近くの立ち寄り施設（ガソリンスタンド・道の駅・SA/PA・展望台）を一覧表示し、Googleマップ（標準URL）で開ける機能。ワンタップで「その施設で募集」も可能 |
| ゆずりあい・交換 | 使わなくなったパーツ・用品・工具を近隣で無償でゆずる・探す・交換するボード。金銭取引は禁止 |

## 4. ペルソナ

### 一般ユーザー
- 20代〜50代、車またはバイクを所有。誘い合える走り仲間・撮影仲間が少ない・引っ越して環境が変わった
- 「週末にワインディングを流したいが一緒に走る相手がいない」「サーキット走行会に参加したいが一人だと不安」
- 恋愛マッチングアプリには抵抗がある（恋愛目的でない人）
- 使わなくなったパーツがガレージに余っているので、誰かに無償でゆずりたい

### ビジネスユーザー
- ガソリンスタンド・整備工場・カー用品店・道の駅・サーキット等の経営者
- 「閑散時間に来店を増やしたい。近くの走り好きとの接点が少ない」「AI接客で問い合わせ対応と、地図から来店への導線を強化したい」
- 月額数千円〜1万円程度の予算感で、新規客よりも「リピーター・常連コミュニティ」を増やしたい

## 5. 機能要件

### 5.1 会員登録・認証

| 要件 | 内容 |
|---|---|
| FR-1-1 | SNS 認証（Apple / Google / LINE）。v1 では電話番号認証を必須としないが、通報対策としてアカウント単位のレート制限を実装 |
| FR-1-2 | 登録時の必須入力：ニックネーム、年代（10歳刻み表示、生年非公開）、性別（非公開も選択可）、居住エリア（市区町村レベル）、興味カテゴリ（複数選択: 国産車/外車・輸入車/旧車・レストア/スポーツカー/ドリフト/サーキット・走行会/峠・ワインディング/ツーリング・ドライブ/バイク/整備・メンテ/洗車・ケア/走り・カー撮影 の12種＋ユーザー自由追加）、車両の話を含む自由記述（140字、「走りともステータス」） |
| FR-1-3 | **アイコンは写真アップロードまたは提供アイコンセットからの選択**。アップロード画像は **本人の素顔** を AI 顔検出で自動審査する方針（本開発）。**車・バイク・整備風景の画像の投稿は許可（推奨）。ナンバーが判読できる画像は投稿不可**の案内を常時表示 |
| FR-1-4 | 年齢確認：生年月日を入力させる（18歳以上チェック用）が、プロフィールには公開しない |
| FR-1-5 | 退会：アカウント削除時のデータ保持期間（アクティブデータ即時削除、バックアップ90日）を規約に明記 |

### 5.2 近くの走りとも・募集（コア機能）

| 要件 | 内容 |
|---|---|
| FR-2-1 | 「募集をかける」：以下を指定して募集を発信できる |
| | - ジャンル（走行会・サーキット / ツーリング・ドライブ / オフ会・ミーティング） |
| | - タイトル・本文（例：「今から海手前のワインディングまで流しに行きます。初心者も安全運転で歓迎」） |
| | - 条件設定：性別指定（任意）、人数上限、車種・走り方の言及（自由記述） |
| | - 有効期限（1 / 2 / 3 時間、期限切れで自動消滅） |
| | - 待ち合わせ場所：施設名（「近くの施設」タブからワンタップで設定可） |
| FR-2-2 | 「近くの人」リスト：現在地から粗い距離（〜1km / 1〜3km / 3〜5km / 5〜10km）で、近くのアクティブな募集・ユーザーを一覧表示。並び替え：距離×新着 |
| FR-2-3 | 検索：ジャンル、キーワード、距離、興味カテゴリでフィルタ可能。「探す」タブからは近くの店舗（業態・店名で検索可）と近くのコミュニティ・イベント（距離近い順）も辿れる |
| FR-2-4 | **近くの施設検索（本アプリの特別機能）**: 現在地周辺の実在の立ち寄り施設を OpenStreetMap（Overpass API）から取得し、近い順に一覧表示（距離バンド、営業時間）。対象は**ガソリンスタンド（amenity=fuel）・道の駅・SA/PA（highway=services）・展望台（tourism=viewpoint）**のみ。**民間の飲食店（cafe等）・公園（leisure=park）は一覧に含めない**。名称のない施設は対象外。Google Maps（Places API）との連携は本リリース時のオプションとして見送り。各施設は「Googleマップで開く」（座標指定の標準URL）でGoogleマップに遷移する。「この施設で募集」ボタンで待ち合わせ場所を初期設定した募集を作成できる。公道では法定速度・マナー遵守の文言を常時表示 |
| FR-2-5 | 募集は同一ユーザーが同時に1件まで（スパム防止） |

### 5.3 応募・交流

| 要件 | 内容 |
|---|---|
| FR-3-1 | 応募：募集詳細から「参加したい」ボタンで応募。一声メッセージ（任意、140字） |
| FR-3-2 | 主催者は応募一覧から承認／却下。承認人数が上限に達したら募集は自動的に締切 |
| FR-3-3 | 承認されたメンバーでグループチャットが自動生成。参加者はその後も辞退可能 |
| FR-3-4 | 1:1 のダイレクトメッセージは募集への応募経由でのみ送れる設計（いきなり DM される対策） |
| FR-3-5 | 万一に備えた安全機能：ブロック／通報は一般ユーザー間と同一水準。初対面の集合・受け渡しは「公共の駐車場・道の駅で」「第三者がいる場所で」行うよう投稿時に案内 |

### 5.4 プロフィール・中身重視設計

| 要件 | 内容 |
|---|---|
| FR-4-1 | 趣味・嗜好の表現をリッチにする（ジャンル、走行スタイル、所有車の系統、整備の考え方、撮影の好み）を「走りともステータス」としてマイページに表示 |
| FR-4-2 | 過去の参加募集数、参加者からの評価（「また一緒に走った」ボタン式、v1.5 実装）を表示 |
| FR-4-3 | ブロック／通報：非表示、通報（理由入力）。通報数が閾値超過で自動凍結 → 人力審査 |

### 5.5 ビジネスユーザー（v1.5）

| 要件 | 内容 |
|---|---|
| FR-5-1 | 店舗登録：店舗名、業態（審査対象: ガソリンスタンド、カーショップ・整備工場、カー用品店、ドライブイン・道の駅、サーキット・走行会場、バイクショップ、レンタカー・レンタルバイク、洗車場、その他）、住所、営業時間、写真（店舗・整備ベイ・車両の画像 OK。**本人の素顔写真禁止は一般ユーザーと同じ基準**） |
| FR-5-2 | **AI接客（有料機能）**: ビジネスユーザーは店舗情報を登録するだけで、AI（LLM）が来店前の質問対応・案内（給油・洗車の可否、整備プラン、料金、営業時間等）を行う |
| FR-5-3 | **地図連携**: 近くの店舗をアプリ内マップ（OpenStreetMap タイル、APIキー不要）にピン表示。各店舗は「Googleマップで開く」（標準URL）。本開発で Google Maps SDK に移行し経路案内まで表示 |
| FR-5-4 | 効果測定: AI接客の応答数・来店導線・閑散時間のアクセス推移を店舗ダッシュボードに表示 |
| FR-5-5 | 課金：月額制（ライト／スタンダード／プレミアム）。決済は Stripe / RevenueCat 等の標準的な手段を利用 |

### 5.6 コミュニティ・イベント

| 要件 | 内容 |
|---|---|
| FR-6-1 | コミュニティ作成：誰でも可（名前、説明、カテゴリ、公開／承認制、地域）。走行会サークル、旧車オフ会、GS常連会等 |
| FR-6-2 | イベント：コミュニティに紐付けて日程・集合施設名・募集人数を設定し、参加受付 |
| FR-6-3 | ビジネスユーザーも一般ユーザーも同じコミュニティに参加可 |
| FR-6-4 | コミュニティ一覧（参加中・未参加とも）は**近い順にソート**する。コミュニティ自身の位置情報は持たず、メンバー・主催者の中で最も近い人までの距離で近さを定義する |

### 5.7 ゆずりあい・交換（パーツ・用品）

| 要件 | 内容 |
|---|---|
| FR-7-1 | 登録: 「ゆずる」（give）「探す」（wanted）「交換」（trade）を、パーツ・用品の特徴（パーツ名・車種・状態）、受け渡し希望地域や施設名、状況・受け渡し方法、**写真1枚（任意。ギャラリー/カメラ）**を入力して登録できる。位置は登録時の現在地（geohash）のみを持つ。写真はパーツ・用品の写るものとし、本人の素顔画像がメインの写真・ナンバーが判読できる写真は投稿不可（一般のアイコンと同じ基準） |
| FR-7-2 | 検索: 近くの登録を**距離近い順**に一覧。ゆずる／探す／交換で絞り込み可。投稿者へのDM導線を同画面に持つ |
| FR-7-3 | 解決: 投稿者は「完了にする」を設定でき、完了は一覧から表示しない |
| FR-7-4 | 法務・安全設計: **金銭取引は本アプリでは行わない**（売買・オークション・送金を禁止。無償の譲り合い・物々交換のみ）。受け渡しは公共の駐車場・道の駅を前提とし、自宅住所など個人を特定できる情報の記入を禁止案内 |

## 6. 非機能要件

| 項目 | 要件 |
|---|---|
| プラットフォーム | iOS / Android（Flutter）。Web 管理画面（モデレーション用） |
| 位置情報プライバシー | 位置情報は端末側で geohash（精度レベル5〜6程度）に変換して送信。サーバーには生の緯度経度を保持しない。退会時に即時削除 |
| セキュリティ | TLS 通信、認証トークン（短期＋リフレッシュ）、パスワードレス（SNS認証） |
| 応答性能 | 募集の一覧取得は P95 200ms 以内（キャッシュ活用）。プッシュ通知は P95 30秒以内 |
| 拡張性 | 趣味カテゴリ（第1弾:飯とも、第6弾:走りとも、次弾:キャンプ/音楽/サウナ/スポーツ/麻雀/ゲーム等）はマスタデータ化し、アプリ再リリースなしで追加可能 |
| モデレーション | AI 審査（**本人の**素顔画像検出、禁止ワード、違法走行募集の検知）＋人力審査ワークフロー。通報 → 凍結 → 審査の SLA 48時間 |
| アナリティクス | 登録 → 募集投稿 → 応募 → 成立（チャット生成） → 実参加（チェックイン）→ リピートのファネル KPI を計測 |

設計メモ：
- 募集の期限切れは毎分のバッチで `status` を `expired` に更新。クライアントは `_expires_at` を見て表示制御も行う（二重防護）
- 施設は外部データ（Google Places / OSM）を `spots` に同期し、`google_place_id` で「Googleマップで開く」URL を組み立てる
- ゆずりあい・交換は geohash 先頭4桁一致（約20km四方）を「近く」とする
- 距離検索は geohash プレフィックス照合で実装し、生の緯度経度での距離計算はクライアント側で行わない

## 9. KPI

| フェーズ | KPI |
|---|---|
| 起動初期（0〜3ヶ月） | 週次アクティブユーザー（WAU）、募集投稿数/日、募集あたり応募数、「施設」タブ→募集作成の転換率 |
| 定着（3〜6ヶ月） | 募集成立率（投稿→チャット生成）、成立後チェックイン率、リピート走りとも率（同一ユーザーと2回以上）、ゆずりあい完了数/月 |
| 収益化（6ヶ月〜） | ビジネスユーザー数（GS・整備工場等）、AI接客経由来店数、解約率、LTV |

初期は車種の近さよりも「募集あたり応募数」が最重要。1.0を下回る場合、リリース地域を都市部のワインディング・GS密集エリアに絞る。

## 10. カテゴリ拡張戦略

第1弾「飯とも」〜第6弾「走りとも！」で共通のプラットフォーム（認証・募集・コミュニティ・地図連携・ビジネス課金）が確立できた前提で、続く拡張（キャンとも！・音とも！・湯とも！・スポとも！・雀とも！・ゲーとも！）は標準化した差分（アプリ名・アイコン・施設・興味カテゴリ・特別ボード）のみで展開する。
